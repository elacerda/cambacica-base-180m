# C4-P1.3b — Bounded synthetic CPU scalability study

**Scientist authorization:** 2026-10-19.
**Status update (2026-10-19): COMPLETE / PASS — SYNTHETIC CPU SCALABILITY ONLY.**
Implementation commit: `22db87a9c35cf532202c051dfe0ce43ea0530fb0`.

This work measures the already authorized C4-P1.3a artificial-token O1
SQLite index, single logical P1 stream producer and acknowledged-window cursor.
It does **not** authorize or perform any C1 production-corpus access,
real tokenization, CUDA/NVML/GPU use, training, optimizer updates,
checkpoint coupling or corpus mixture selection. No frozen C1/C2/C3
implementation is changed.

## Instrument and scope

New files:

- `src/cambacica/packing/p1_scalability_synthetic.py`: standard-library-only
  benchmark CLI/API that generates **only artificial token IDs**, builds
  a new temporary P1.3a O1 index and iterates/acknowledges the train windows.
- `tests/packing/test_p1_scalability_synthetic.py`: parameter limits, empty
  synthetic documents, 4096 boundaries, artificial EOS/target accounting,
  deterministic order/window acknowledgment, variable fragment sizes,
  cursor re-instantiation/replay, and CLI errors/cleanup.
- This design/evidence record; the original P1.3a implementation is unchanged.

Artificial documents are generated by a deterministic arithmetic pattern
of valid vocabulary IDs **3–24575**; `EOS=2` is emitted once by the P1.3a
index for each document. The benchmark takes only a document count,
per-document token count, fragment size, optional *in-process* replay
injection after N acknowledgments, and optional scratch parent. No
text or real C1 coordinates enter the generator. The view and seed strings
are **prototype-only**, not adopted production sampling policy.

A single case creates a fresh temporary directory (removed afterward),
spools the fixture through `SyntheticDiskIndex.build`, then iterates
`SyntheticWindowConsumer.next_window` and `acknowledge` until exhaustion.
It validates `max(L-1,0)` owned targets, correct scored inserted EOS,
contiguous window positions, successful cursor acknowledgments and (if
requested) equality of the delivered-but-unacknowledged window across
consumer re-instantiation. A replay check **does not kill the process**;
it is not a proof of crash consistency under power loss.

### Resource and performance measurements

Every case reports machine-readable JSON containing:

- observed `build_seconds`, `window_read_seconds`, `ack_fsync_seconds`,
  `resume_verify_seconds` and `total_seconds`, based on `perf_counter`;
- SQLite database bytes, artificial payload bytes, index manifest bytes,
  acknowledged cursor bytes and combined index bytes;
- `peak_process_rss_kib` from Linux `resource.getrusage(RUSAGE_SELF)`;
- document, stream-token, scored-label, EOS, window and replay counts;
- view/order SHA-256 digests and final acknowledgment-chain SHA-256.

**Measurement cautions:** Peak RSS includes Python/runtime libraries and
is a **process-wide high-water mark**, not the incremental memory of one
function or SQLite. Each independent CLI process must measure one case;
do not compare high-water marks obtained from sequential calls within
one process. RSS varies by host, page cache and runtime. `ack_fsync_seconds`
includes a sync/atomic cursor write **per window**; scan throughput here
is not pure token decoding rate or training throughput. Disk sizes depend
on SQLite page layout and filesystem; no I/O read/write counters or CPU
utilization percentages are claimed.

### Safety caps

One invocation requires an explicit positive `--documents` value and
`--tokens-per-document` (zero permitted for an empty-document fixture).
It rejects more than **50,000 synthetic documents**, more than **16,384
artificial tokens per document**, and more than **2,000,000 total stream
tokens**. Fragment size is bounded by 1–4097. The benchmark never
accepts corpus input filenames, downloads datasets, opens a tokenizer,
or selects a GPU. Use a scratch parent on **local ext4** for comparable
Orion disk measurements; temporary outputs are automatically removed.

## Local synthetic measurements — provisional, not Orion

Three cases were run independently in an isolated container, one fresh
Python process per case, with artificial fixture tokens and
`CUDA_VISIBLE_DEVICES=""`, on 2026-10-19. They are **local observations**
and cannot be extrapolated to Orion, a 21.6-million-document corpus,
real tokenizer output or pretraining duration.

| Documents × tokens/doc | Stream tokens | Windows | Peak RSS (KiB) | SQLite bytes | Payload bytes | Build (s) | Read (s) | Ack+fsync (s) | Resume (s) | Total (s) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 128 × 128 | 16,512 | 5 | 99,352 | 102,400 | 32,768 | 0.0711 | 0.0266 | 0.0413 | 0.1101 | 0.2585 |
| 1,024 × 128 | 132,096 | 33 | 104,224 | 634,880 | 262,144 | 0.2081 | 0.4990 | 0.3793 | 0.0149 | 1.1130 |
| 8,192 × 128 | 1,056,768 | 258 | 156,452 | 4,845,568 | 2,097,152 | 1.3250 | 7.3809 | 6.2234 | 0.0760 | 15.0861 |

Restart injection occurred after 1, 8 and 32 acknowledged windows,
respectively. Timings include filesystem effects and measurement noise;
in particular, the first tiny-case resume time was not monotonic.
The larger case shows **cursor fsync cost is material** relative to window
reading (6.22 s versus 7.38 s in this container). No production
checkpoint cadence, batching optimization or concurrency policy is
implied or approved by that finding.

The isolated local unit suite reported **20 passed** and Python compile
checks passed. It ran against the available local P1.3a working copy and
an interface-compatible local reference **stand-in**; it is **not**
verification against the checked-in full P1 reference in the Orion
repository. Ruff was not available in the isolated environment.

All three reports included `fixture_only: true`, `resume_checks: 1`,
and respectively 128, 1,024, 8,192 scored EOS tokens. Their scored
next-token targets were **16,511**, **132,095**, and **1,056,767**:
each is exactly `stream_tokens - 1`. Each run returned a final
order SHA-256 and acknowledgment-chain SHA-256 in its JSON.

**Interpretation and limits:** observed peak process RSS ranged from
approximately **20.64 MiB** to **23.40 MiB** over 64× more
artificial documents, consistent with bounded resident memory over
these fixture sizes. This is **not** a proof of a constant-memory
production loader. The largest case spent **2.415402 s in ack + fsync**,
about **43.5%** of the measured **5.546933 s read-and-ack phase**;
this identifies cursor persistence as a candidate for later, separately
approved optimization, not authorization to change snapshot cadence.
Each size was run only once. Disk/index costs, memory, timing and
resume behavior must **not** be extrapolated to C1's 21.6M documents,
production tokenization, or model training; injected restart is
in-process replay, not a power-failure test.

**Gate decision:** the authorized bounded P1.3b synthetic CPU
scalability study is **COMPLETE / PASS**, with test, format, three-scale
measurement and published-commit evidence. The complete C4 pipeline
is **IN PROGRESS**.

## Orion validation commands (executed; retained for reproduction)

Validation was performed on Orion using the new files after formatting;
these commands are retained as reproducibility instructions. Run one
size **per Python process** if repeating the measurements:

```bash

  tests/packing/test_p1_scalability_synthetic.py

  tests/packing/test_p1_scalability_synthetic.py

  tests/packing/test_p1_scalability_synthetic.py
CUDA_VISIBLE_DEVICES="" PYTHONPATH=src \
  /srv/cambacica-c3/venv/bin/python -m pytest -q \
  tests/packing/test_p1_scalability_synthetic.py \
  tests/packing/test_p1_streaming_synthetic.py \
  tests/packing/test_p1_reference.py
CUDA_VISIBLE_DEVICES="" PYTHONPATH=src \
  /srv/cambacica-c3/venv/bin/python -m pytest -q

# Select and verify a scratch parent on local ext4 before running.
# Do not run on the live C1 source tree, NFS or a shared GPU workspace.

findmnt -T "$SCRATCH_PARENT" -no FSTYPE,SOURCE,TARGET
for row in '128 1' '1024 8' '8192 32'; do
  set -- $row
  CUDA_VISIBLE_DEVICES="" PYTHONPATH=src \
    /srv/cambacica-c3/venv/bin/python -m \
    cambacica.packing.p1_scalability_synthetic \
    --documents "$1" --tokens-per-document 128 \
    --restart-after "$2" \
```

verified existing local ext4 directory. The command above prints
JSON to stdout; store it in a user-selected report directory if needed.

be approved without repeat measurements on Orion, resource monitoring,
and scientific review of the scaling curves.
